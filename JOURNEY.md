## 2026-08-15 — Sesión 2: tokenizador (Learning Go cap. 3)
- **Qué se hizo:** módulo `02-tokenizador` — CLI que toma texto desde `os.Args`, lo tokeniza y cuenta frecuencias en un `map[string]int`. `gofmt`, `go vet` y `go build` limpios.
- **Qué se aprendió:** `strings.Fields` vs. `strings.Split` (colapsa espacios/tabs/saltos de línea vía `unicode.IsSpace`, descarta vacíos en los bordes); la shell parte `os.Args` por espacios *antes* de que el programa arranque, salvo que el usuario use comillas; un `map` con `var` sin `make` panickea al escribir pero no al leer; leer una key inexistente devuelve el zero value del tipo valor, por eso `counts[token]++` funciona sin chequeo previo; `strings.TrimFunc`/`unicode.IsPunct` solo pelan los *extremos* de un string. Fidel fue más allá de lo sugerido: usó `strings.FieldsFunc` con un predicado propio (`!IsLetter && !IsNumber`) que limpia puntuación en *toda* la palabra, no solo los bordes — generalización correcta del problema, no solo de la solución que se le dio.
- **Qué costó:** la sesión arrancó con culpa por una semana floja de estudio; se reencuadró como parte normal del proceso, no como fracaso. Confundir `strings.ContainsAny` (firma `(s, chars string) bool`) con un predicado `func(rune) bool` válido para `TrimFunc` — error de forma de función, no de nombre.
- **Qué sigue (pregunta abierta para la próxima sesión):** el predicado actual trata `-` y `'` igual que cualquier signo de puntuación, así que `"e-commerce"` y `"don't"` se fragmentan en tokens falsos (`e`, `commerce`, `don`, `t`). Decidir *a propósito* — pensando en el proyecto norte (motor de búsqueda full-text) — si guion y apóstrofo deberían preservarse como parte del token o seguir tratándose como separadores, y dejar la razón documentada en el código. Después: commit + push (hecho), abrir PR.
- **Qué se hizo:** módulo `01-fundamentos` con `filereader.go` — CLI que valida argumentos, lee un archivo completo con `os.ReadFile` y maneja errores con mensaje a stderr + exit code correcto. Las 3 pruebas (archivo válido, sin args, archivo inexistente) pasan; `go vet` y `gofmt` limpios.
- **Qué se aprendió:** `os.Args[0]` es el nombre del programa (el bug del uróboro: el programa se leyó a sí mismo y escupió un header ELF); slice `nil` ≠ slice corto → validar con `len`; error-valor vs. panic del runtime (los panics se previenen, no se cachean); `panic`/`check` de Go by Example es anti-patrón — el idioma es `if err != nil` en el sitio; `os.Exit` no ejecuta los `defer`; errores a stderr, no stdout; verbos de `fmt` eligen representación (`%T`, `%v`, `%q`, `%s`), no declaran tipo como en C; `os.Open` (bajo nivel, trozos) vs. `os.ReadFile` (alto nivel, todo en memoria).
- **Qué costó:** la condición de longitud de `os.Args` (dos intentos fallidos: `== nil`, `< 1`); descifrar el output binario del primer run; soltar el hábito de copiar patrones sin entenderlos.
